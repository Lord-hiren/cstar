## Goal
Close known issues #7, #8 and #10, each with a regression test, so that Phase 3 ends with no open known issue.

## Purpose
- **#7 is part of a larger cluster.** A differential of 5,705 (value, spec) pairs against Python 3.12 found more than
  the regrouping corner. `format(-42, "08.2f")` prints `00-42.00` (Python `-0042.00`), and explicit fills and
  alignments are ignored when combined with the `0` flag. Width counts bytes, not code points. One rewrite of the
  padding step fixes them all.
- **#10 returns silent wrong values.** `fvec % x` divides or multiplies.
- **#8 litters `$TMPDIR`** whenever caching is off.

## Output
- One numeric-layout helper in the runtime, ported from CPython's `calc_number_widths`/`fill_number`, and code-point
  width/precision/fill.
- A type guard for `fvec %`.
- A driver that unlinks a cache-less binary before it runs.
- Regression cases `bi_py_format_pad` and `rt_fvec_mod`, and the harness check `cacheless_cleanup`.
- SPEC rules written down; the known-issues registry empty.
</objective>

## What the survey established (2026-11-11, WSL, Python 3.12.3)
**#7 / format.** Two generated probes (`scratchpad/p0302/gen.py` and `gen2.py`) compared cstar and Python on every
pair Python accepts:
- Grid 1: 4,995 pairs (zero, sign, `=`, fill, grouping, `.Nf` × 13 values × widths 0–14) → **1,387 mismatches**.
- Grid 2: 710 pairs (explicit fill + `0`, `#` prefixes, text, non-ASCII, bool, `c`, typeless float, `e`/`g`/`%`)
  → **242 mismatches**.

| Defect | Example (cstar → Python) |
|---|---|
| zero padding + `,` doesn't regroup (**#7**) | `format(42, "08,")` `00000042` → `0,000,042` |
| float zero padding goes before the sign | `format(-42, "08.2f")` `00-42.00` → `-0042.00`; `format(-0.5, "010")` `000000-0.5` → `-0000000.5` |
| float `=` padding goes before the sign | `format(-0.5, "=10")` `      -0.5` → `-      0.5` |
| an explicit fill is replaced by `0` | `format(42, "*>05")` `00042` → `***42`; `format(255, "#>05x")` `000ff` → `###ff` |
| `0` flag + explicit `<`/`^`/`>` | `format(0, "<010,")` `0         ` → `0000000000`; `format(-42, ">010")` `-000000042` → `0000000-42` |
| `0` flag on text and `c` ignored | `format("ab", "05")` `ab   ` → `ab000`; `format(65, "05c")` `    A` → `0000A` |
| width counts bytes, not code points | `format("héllo", ">9")` `   héllo` → `    héllo` |
| precision counts bytes | `format("héllo", ".3")` `hé` → `hél` (a byte cut can split a UTF-8 sequence — SPEC: text never splits) |

- **The root cause is one step.** CPython resolves the fill and alignment, then lays out
  `[lpad][sign][prefix][spad][digits][rest][rpad]`:
  - the `0` flag sets fill `0` when no fill is given, and alignment `=` when no alignment is given (numbers only);
  - with fill `0` and alignment `=`, the digit run itself is zero-extended and grouped to the remaining width;
  - inf/nan have no digits, so they are never grouped (`format(inf, "010,")` → `0000000inf`).
- **Bool is not a defect.** It accounts for all 48 bool mismatches (`format(True, "5")` is `True ` in cstar, `    1` in
  Python): bool is its own type in cstar (`True == 1` is `False`, gotchas). It stays as is and gets documented.
- **Error parity is out of scope.** Some specs Python rejects are accepted by cstar (a sign or `=` on text; a sign on
  `c`), and `,` with `e`/`g`/`%` is rejected by cstar. Both are recorded as D-13, not fixed here.

**#8.** The repro is confirmed: `$TMPDIR/cstar-XXXXXX/program` is left behind. A spike (`scratchpad/p0302/fexec_spike.c`)
showed that opening the binary O_RDONLY|O_CLOEXEC, unlinking it, rmdir-ing its directory and calling `fexecve` works:
- same pid, same argv, exit code passed through (7 → 7), directory gone;
- the only visible difference is `/proc/self/exe` ending in ` (deleted)`. The runtime never reads it (it uses only
  argv, via `cs_init`).
- The process is still *replaced*. Signals, exit codes, stdin and pipes behave exactly as today, with no fork,
  forwarding or reaper.

**#10.** The repro is confirmed: `[2.5, -2.5] [4.0] [inf]`, exit 0.
- Scalar `5.0 % 2.0` already raises `unsupported operand types for %: float and float`.
- The fused fvec kernel (`emit_fvec_assign`) only takes `+ - *` and unary `-`. `%` always reaches `cs_mod` →
  `cs_vec_binop`, so a guard there covers every path, `%=` included.

    **SPEC first.** Extend the `format` row in §5.11.3 (same row, no renumbering) with these rules:
    - the `0` flag means fill `0` when no fill is given, and alignment `=` for a number with no explicit alignment;
      an explicit fill wins over the `0` flag;
    - `=` pads after the sign and after a `0x`/`0b`/`0o` prefix;
    - with fill `0` and `=`, `,` regroups the zero-extended digit run: `format(42, "08,")` → `0,000,042`, and the
      result may exceed the width by one character;
    - `inf`/`nan` are never grouped;
    - width, precision and fill count code points.

    In §5.11.5 ("every observable difference from CPython is listed here"), append item 16 for `format`:
    - `bool` formats as its text, not as a number (`format(True, "5")` → `True `, `"d"` → ValueError);
    - `,` requires `d`/`f`/typeless (Python also allows `e`/`g`/`%`);
    - a sign, `=` or `,` on a text spec, and a sign on `c`, are accepted where Python raises.

    These record today's behaviour; whether to close them is D-13.

    **Runtime (`cs_format_apply` only).**
    - **Spec parse.**
      - Record whether a fill and an alignment were given.
      - The fill may be any single code point (a multi-byte UTF-8 sequence followed by an alignment character).
      - After parsing: if the `0` flag is set and no fill was given, fill = `0`. If additionally no alignment was given
        and the value formats as a number (numeric types and the `c` code), alignment = `=`.
    - **One layout helper for both numeric paths**, ported from CPython:
      - split the number into sign (`-`, or `+`/space from the sign option), prefix, leading digit run, and rest
        (decimal point, fraction, exponent, `%`, or `inf`/`nan`);
      - if fill is `0` and alignment is `=`, the min width of the digit run is width − (sign + prefix + rest);
      - group or zero-extend the digit run with CPython's `_PyUnicode_InsertThousandsGrouping` loop (groups of 3; never a
        leading separator; an empty run is never grouped);
      - pad what is left by alignment: `<` right, `^` split (left = n/2), `=` between sign/prefix and digits, `>` or
        unset left;
      - remove `cs_add_grouping` (it becomes unused, so clang would warn).
    - **Text and `c`.** `cs_pad_align` counts code points and takes a UTF-8 fill. Text precision truncates to N code
      points. `=` on text keeps today's right alignment (its error parity is D-13).
    - **Unchanged:** every error check and message, bool's text path, `s`/`r`/`c` dispatch, and the typeless display
      forms.

    **Regression case `bi_py_format_pad.cst`** (line 1: what it proves, SPEC §5.11.3, known issue #7). About 70
    curated lines from the grids:
    - every row of the survey's defect table;
    - inf/nan via `float("inf")` / `float("nan")` if cstar parses them;
    - unchanged specs as controls.
    Generate `.out` by running the same expressions in python3. cstar must match it byte for byte; review the file by
    hand.

    Avoid: changing the grammar subset, error messages, or bool behaviour, and adding error parity (D-13).
