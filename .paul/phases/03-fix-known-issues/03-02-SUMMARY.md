# Phase 3 Plan 02: format parity, cache-less cleanup and fvec % — Summary

**No known issue is open any more.**
- `format()` now gives Python's text for every spec in cstar's subset. The one reported corner, #7, turned out to be
  part of a cluster of seven defects in the same padding step.
- A run that cannot cache leaves nothing behind.
- `fvec % x` raises the same `TypeError` as `float % x`.

## Accomplishments

- **`format()` is a faithful port, not a patch.** Both numeric paths share CPython's layout
  (`[lpad][sign][prefix][spad][digits][rest][rpad]` with `InsertThousandsGrouping`). Fill and alignment resolve the
  way Python does. Text is measured in code points, so a precision cut can no longer produce invalid UTF-8.
- **The cache-less run has the same process model.** The driver is still replaced by the program (same pid,
  signals, exit status), with no fork, reaper or signal forwarding. The kernel frees the unlinked binary when the
  program exits.
- **Every fix has a deterministic guard that fails on the old build.** The format case's expected output was
  generated by Python itself.

## Decisions Made

| Decision | Rationale | Impact |
|----------|-----------|--------|
| Fix #7 together with the padding cluster (planned) | The differential showed one root cause. A narrow regroup fix would have left `00-42.00` | `format()` matches Python on its subset |

### Auto-fixed Issues

**1. [Runtime] Long `f` results died with "out of memory"**
- **Found during:** Task 1 (the edge probe).
- **Issue:** the float path formatted into a fixed 160-byte buffer and raised the uncatchable `out of memory` when
  the result did not fit. `format(1e300, ".0f")` has 301 digits; a large precision fails the same way. The old
  compiler failed identically.
- **Fix:** keep the stack buffer and redo the formatting once in an exact-size heap buffer when the result is
  longer.
- **Files:** `runtime/cstar_rt.c`.
- **Verification:** `format(float("1e300"), ",.0f")` matches Python, and it is a line of `bi_py_format_pad`.
- **Commit:** `8e21755`.

### Scope Additions

1. **bool and the `0` flag.** The plan's boundary said "bool formatting unchanged". It became "bool formats exactly
   like its text", so the `0` flag now fills it with `0`: `format(True, "05")` changes from `True ` to `True0`. The
   same applies to `None` (`None00`). This follows from fixing the `0` flag on text, avoids a bool special case, and
   is stated in SPEC §5.11.5 item 16.
2. **SPEC §5.11.5 item 16 is broader than planned.** Besides bool, `,` and the lenient text options, it records two
   pre-existing differences the edge probe found:
   - `None` and collections format as text where Python raises a `TypeError`;
   - malformed specs use cstar's shorter messages.

   §5.11.5 claims to list every observable difference, so leaving them out would have made it untrue.

### Deferred Items

None new. D-13 (whether to close the format error-parity deviations) was logged at plan time and is now documented
in SPEC §5.11.5 item 16.
