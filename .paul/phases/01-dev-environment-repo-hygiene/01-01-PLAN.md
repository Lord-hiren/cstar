<objective>
## Goal
Make the compiler buildable and testable from this Windows machine through WSL (Ubuntu), fix the line
endings that would break the build, and record a baseline of `make test`, the editor smoke test and the
docs checker.

## Purpose
Until now, no change to cstar can be verified on this machine: the toolchain is Linux-only and WSL isn't
installed. Every later plan (the rename, bug fixes, the Windows port) needs a working `make test` and a known
starting point to compare against.

## Output
- WSL Ubuntu with clang, make, libcurl dev headers and python3
- `.gitattributes` that forces LF line endings, so Windows checkouts stop breaking the bash scripts and test files
- `01-01-BASELINE.md`: tool versions, test results and timings
- Windows/WSL build instructions in `CLAUDE.md` and `docs/guide/getting-started.md`
</objective>

## Facts found during planning (2026-11-04)
- The system git config (`C:/Program Files/Git/etc/gitconfig`) has `core.autocrlf=true`. All 1,063
  tracked text files are checked out with CRLF (`git ls-files --eol` shows `i/lf w/crlf`); the index stores LF.
- In WSL, CRLF breaks `tests/run_tests.sh` (`$'\r': command not found`). It would also make every
  byte-exact `.out` comparison fail, because programs print LF.
- There is no `.gitattributes` in the repo.
- `wsl.exe` exists, but no distribution is installed ("The Windows Subsystem for Linux is not installed").
- Windows already has `node`; there is no Windows `python`.
- The repo is at `C:\work\project\cstar\Pentest`, which is `/mnt/c/work/project/cstar/Pentest` inside WSL.

## Decision made in this plan (override at approval if you disagree)
**Keep the Windows working copy and build it from WSL through `/mnt/c`**, rather than making a second
clone inside the WSL filesystem.
- **Why:** the current editor and Claude Code workflow on Windows keeps working unchanged.
- **Trade-off:** builds over `/mnt/c` are somewhat slower than on the native WSL filesystem.
- **Required by this choice:** LF line endings in the Windows checkout, which `.gitattributes` provides.
  This moves the `.gitattributes` part of repo hygiene from 01-02 into this plan.
