<objective>
## Goal
Rename every internal Pentest name in the compiler, runtime and build to cstar. Prove that the generated
programs behave byte-for-byte the same, then update every living reference to the new names.

## Purpose
After 02-01 to 02-03, users see cstar everywhere, but contributors still read `pt_value`, `pentest_rt.c`,
`namespace pentest` and `__ptm`. The user chose to rename the internals too (decision 2026-11-05). Doing it
now, before Phase 3 touches the runtime (#9 text growth), means later diffs and docs use the final names.

## Output
- `runtime/cstar_rt.{h,c}` (history kept). The `cs_`/`CS_` prefixes, `namespace cstar` and `__csm<id>_`
  mangling are used throughout `src/`, the runtime, `tools/embed.cpp` and the Makefile
- Code comments and the HTTP User-Agent say cstar; legacy behaviour (`pentest` alias, `PENTEST_PATH`,
  `.pen`/`.pent`) is untouched
- SPEC, contracts, living docs, CLAUDE.md, README, bench sources and test comments use the new names;
  historical docs get a one-line note
</objective>

**Findings that make the rename safe:**
- **New prefixes:** `cs_`, `CS_`, `cstar_rt`, `CSTAR_RT_H`, `namespace cstar`, `cstar::` and `__csm` do not
  appear anywhere in `src/`, `runtime/` or `tools/`.
- **Same length:** `cs_`, `CS_` and `__csm` match the length of `pt_`, `PT_` and `__ptm`, so prefix
  arithmetic stays valid, e.g. [ast.h:357](src/ast.h) `compare(0, 5, "__ptm")`.
- **User names keep their separation:** user names are emitted under the same prefix (`pt_g_<name>`,
  `pt_l_<name>`), and a uniform prefix swap preserves the separation between runtime names and user names.
- **Word boundaries:** the only "mid-word" matches are unrelated names (`except_clause`,
  `CURLOPT_*`), which the `\b` rule leaves alone.
- **Tests:** no test expectation (`.out`/`.err`) contains an internal name. Six `.cst` files mention them,
  in comments only.
- **Links and headings:** one markdown link points into the runtime (docs/reference/known-issues.md:49).
  One contract heading names the file (m2a-semantics.md §10; its number does not change).

## Mapping (applied with word boundaries, in this order)
| Old | New |
|-----|-----|
| `pentest_rt` (file names, includes, `build/pentest_rt.o`, embed names) | `cstar_rt` |
| `PENTEST_RT_H` / `PENTEST_BUILTINS_H_` | `CSTAR_RT_H` / `CSTAR_BUILTINS_H_` |
| `namespace pentest`, `pentest::` | `namespace cstar`, `cstar::` |
| `__ptm` | `__csm` |
| `\bpt_` | `cs_` |
| `\bPT_` | `CS_` |

**Kept on purpose:**
- **Legacy behaviour:** the `pentest` alias (Makefile `build/pentest`, main.cpp), `PENTEST_PATH`,
  `.pen`/`.pent`, and the legacy code paths in the extension.
- **Historical records:** `docs/history/*`, `docs/performance/baseline-*.md`, `bench/results/*`,
  `tools/hpcbench/RESULTS.md`, released CHANGELOG entries and `.paul/phases/*`. They describe the past;
  each doc gets a note instead of an edit.
- **Frozen tools:** `bench/run.sh` (it describes the frozen `bench/tools/pentest-m1`) and the binary itself.
- **`tools/hpcbench/*`:** still `.pen` workloads and `build/pentest`. Both work until v0.4; logged as D-11.
